C. MARKDOWN RENDERING

The article body contains Markdown. Render it as formatted content rather than plain text.

Use the project’s existing Markdown renderer if one exists. Otherwise use a maintained Markdown renderer compatible with the current framework.

Support:

- H2 and H3 headings
- Paragraphs
- Bold and italic text
- Bulleted and numbered lists
- Links
- Blockquotes
- Horizontal rules

Sanitize rendered output. Do not use unsafe raw HTML injection.

Do not display the body using one plain `<div>` or `<p>` containing the entire content string.

D. ARTICLE PAGE LAYOUT

Create a clean, readable article layout consistent with the existing Adapy.com design:

1. Existing site header
2. Back to Blog link
3. Category badge
4. Article title as one H1
5. Excerpt
6. Published date
7. Large featured image
8. Properly formatted article body
9. Existing site footer

Use:

- A readable content width of approximately 760–850px
- Responsive typography
- Comfortable paragraph spacing and line height
- Clear H2/H3 hierarchy
- Proper spacing for lists
- No text overlap
- No raw Markdown characters

E. FEATURED IMAGE

The publishing endpoint must accept:

- featuredImageUrl
- featuredImageAlt

Save both values with the article.

On the public article page:

- Display the image below the title/excerpt area.
- Use a responsive 16:9 container.
- Use `object-fit: cover`.
- Preserve rounded corners consistent with the website.
- Use meaningful alt text.

On the blog listing cards:

- Use the same featured image.
- Keep the image in a fixed responsive aspect-ratio container.
- Do not place the article title inside the image container.
- Do not allow the category badge to overlap the title.
- Do not render a broken-image icon.

F. IMAGE FALLBACK

Add or use an existing Adapy-branded fallback blog image when `featuredImageUrl` is missing or fails to load.

Requirements:

- Confirm the fallback asset actually exists in the deployed project.
- Do not reference an imaginary file path.
- If the remote image fails, switch to the verified fallback.
- The card and article page must never show a broken image icon.
- Do not use the article title as an image URL or image source.
